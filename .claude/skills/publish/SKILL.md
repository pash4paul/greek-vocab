# Публикация

Сайт статический, деплой бесплатный, каждый пуш в `main` пересобирает его сам.

## Сначала — проверка

```bash
npm run check && npm run build
```

Если не прошло — не публикуй, сначала починить. В CI стоит тот же `npm run check`,
так что сломанный словарь просто не доедет, но узнать об этом лучше здесь.

## Если репозитория ещё нет

`gh` в системе не установлен, поэтому репозиторий владелец создаёт через сайт.
Попроси его создать **пустой** репозиторий на github.com (без README и .gitignore)
и прислать адрес. Дальше:

```bash
git init
git add -A
git commit -m "Тренажёр греческих слов"
git branch -M main
git remote add origin git@github.com:<username>/<repo>.git
git push -u origin main
```

Затем владелец включает публикацию: **Settings → Pages → Source → GitHub Actions**.
Это единственный шаг, который нельзя сделать из терминала — так и скажи.

Через пару минут сайт будет по адресу `https://<username>.github.io/<repo>/`.
Workflow уже лежит в `.github/workflows/deploy.yml`, настраивать его не надо:
`BASE_PATH` подставляется из имени репозитория автоматически.

## Если репозиторий уже есть

```bash
git add -A
git status          # покажи владельцу, что уходит
git commit -m "<что изменилось: например, добавлена тема «Одежда», 40 слов>"
git push
```

Коммить только когда попросили. Сообщение — по-русски, по делу: что изменилось,
а не «update files».

## После публикации

Скажи владельцу:

- адрес сайта;
- что на телефоне приложение ставится на домашний экран (Safari → «Поделиться» →
  «На экран "Домой"») и после этого работает офлайн;
- что **прогресс не переносится сам** — он живёт в браузере. Между устройствами
  переносится через Настройки → Данные → Экспорт/Импорт;
- что озвучка работает в Safari, а в Chrome молчит (баг браузера, обойти
  не удалось).

## Проверить, что выкатилось

```bash
gh run list --limit 3     # если gh появится
```

Иначе — вкладка Actions в репозитории. Если сборка упала, смотри шаг
«Проверить словарь»: почти всегда это опечатка в yaml, а не поломка кода.
