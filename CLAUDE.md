# Ελληνικά — тренажёр греческих слов

Приложение для заучивания греческих слов интервальными повторениями.
Владелец учит греческий по учебнику, слова попадают сюда со скриншотов уроков.

**Владелец проекта — не обязательно инженер.** Объясняй результат по-русски и
по делу, не отправляй читать код. Если нужно решение — предлагай вариант,
а не список альтернатив.

## Как устроено

```
data/*.yaml                 словарь, единственный источник правды
   ↓  scripts/build-deck.mjs      валидация + вывод форм по правилам
src/generated/deck.json     собранная колода (в git не хранится)
   ↓  vite
приложение (React, PWA)     прогресс — только в браузере, IndexedDB
```

Одно слово даёт **до пяти карточек**, открывающихся по очереди:
`recognize` (EL→RU) → `listen` (на слух) → `produce` (ввод RU→EL) →
`cloze` (пропуск в предложении) → `case` (падежи, только существительные).
Следующая ступень появляется, когда предыдущая вышла из фазы обучения.
Расписание считает FSRS (`ts-fsrs`).

## Команды

```bash
npm run check        # тесты правил + валидация словаря. Запускать всегда после правки data/
npm run dev          # локально на http://localhost:5173
npm run build        # прод-сборка
npm run test:morph   # только тесты правил словоизменения
npm run test:tts     # только тесты озвучки (на подделке Web Speech API)
npm run test:storage # только тесты переноса прогресса (экспорт → импорт)
npm run test:session # только тесты поведения артикля в упражнениях
npm run simulate     # прогон 60 учебных дней: видно, во что превратится нагрузка
npm run fetch:cases  # добрать падежные формы из Викисловаря
```

## Коммиты — только по-английски

Сообщения коммитов пишутся **на английском**, даже когда весь остальной разговор
идёт по-русски. Это относится и к заголовку, и к телу.

```
Show the answer in the card review

The review pane never displayed what the question asked for: no translation
on recognition cards, and not even the written form on listening cards.
705 of 786 words have no example, so there was no hint at all.
```

Комментарии в коде, `CLAUDE.md`, `README.md`, тексты интерфейса и словарь
остаются по-русски — правило касается только истории git.

Проверяется механически хуком `githooks/commit-msg`: коммит с кириллицей
в сообщении не пройдёт. Хук включается один раз на клон —
`git config core.hooksPath githooks`, в этой копии уже включён.
Разовый обход, если он зачем-то нужен: `git commit --no-verify`.

## Правила, которые нельзя нарушать

**0. Артикль — часть слова, а не украшение.** Он показывается в вопросе,
требуется в ответе при вводе, входит в падежные формы и **произносится**.
Озвучка идёт через `spokenForm()`, а не через `word.el`: иначе слышно «σπίτι»,
а написано «το σπίτι», и на карточке аудирования род вообще не узнать.
Исключение одно: в упражнении с пропуском артикль уже виден в предложении,
поэтому в ответ его вписывать не надо. Закреплено в `scripts/session.test.mjs`.

**1. Не подгонять правило под одно слово.** В `scripts/morphology.mjs` живут
регулярные парадигмы. Если правило разошлось с реальной формой — это почти
всегда исключение в языке, а не ошибка правила. Помечай слово `irregular: true`
и вписывай формы руками. Подгонка правила под `τρώω` сломает сорок правильных
глаголов, и заметишь ты это через месяц.

`irregular: true` **только глушит предупреждение о расхождении**. Сам по себе
он ничего не заменяет: не впишешь формы — в колоду уйдут выведенные правилом,
причём молча. Флаг без `cases:` или `forms:` рядом почти всегда недоделка.

**2. Любое изменение правил — с тестом.** `scripts/morphology.test.mjs`,
303 проверки на заведомо известных парах. Правила существуют затем, чтобы быть
надёжнее человека; непроверенное правило этого свойства не имеет.

**3. Не менять поле `el` у существующего слова.** Идентификатор карточки
строится из греческой формы без ударений (`slugify`). Правка `el` создаёт новое
слово и **обнуляет прогресс** по старому. Перевод, пример, формы, тему, часть
речи менять безопасно — прогресс переживёт.

**4. Не редактировать `src/generated/deck.json`.** Он пересобирается при каждом
запуске, правки затрутся. Менять надо `data/*.yaml`.

**5. Не глушить предупреждения сборки.** Скрипт сообщает о расхождениях с
правилами, дублях и незаполненных клетках намеренно. Пустая клетка честнее
выдуманной формы: упражнение просто не спросит её.

## Приоритет источников для падежных форм

```
руками (ключ cases: в yaml)  →  Викисловарь  →  правила
```

Викисловарь (`npm run fetch:cases`) заполняет только то, что правила выводить
отказались. Выведенное он не перетирает, а расхождения печатает списком —
разбирать их надо вручную, потому что ошибка может быть с любой стороны.
Дважды уже была моя: артикль `την` и множественное у профессий на `-ης`.

Первые два источника работают **и без третьего**: отказ правила не выбрасывает
таблицу, а оставляет в ней пустые клетки. Так было не всегда — до августа
2026 отказ правила уносил с собой и `cases:`, и Викисловарь, поэтому у
словосочетаний ручные формы молча ни на что не влияли, а у `το κρέας`
родительный из Викисловаря был, а именительного не было вовсе.

**Словосочетания правилам не по зубам, и они честно отказываются.** Правила
читают конец строки и правят ударение в ней же, то есть считают запись одним
словом. У `εμπορικό κέντρο` выходило `του εμπορικο κέντρου` — определение не
согласовано, да ещё и без тоноса, потому что правило трёх слогов отсчитало их
от конца всей строки. Все семь словосочетаний в словаре заполнены руками.

## Что уже проверено и переспрашивать не надо

- **Озвучка работает в Safari, в Chrome — нет.** Голоса в Chrome числятся,
  но `speechSynthesis` молчит. Обходы в `src/lib/tts.ts` (сторожевой таймер,
  повтор, удержание ссылки на фразу) уже стоят. Диагностика — в приложении:
  Настройки → Озвучка → «Проверить озвучку».
- **`speechSynthesis.cancel()` нельзя звать на простаивающем движке.**
  В WebKit это сбрасывает разрешение, выданное жестом пользователя, и
  автоматическая озвучка замолкает, хотя по кнопке всё работает. Отменять
  только при `speaking || pending`.
- **`onstart` в WebKit приходит не всегда.** Судить по нему о том, звучит ли
  фраза, нельзя: сторожевой таймер решал, что фразу выбросили, и повторял её —
  слово произносилось дважды. Состояние надо спрашивать у движка
  (`speaking || pending`), а свой флаг использовать лишь как подсказку.

  Все три бага озвучки закрыты тестами в `scripts/tts.test.mjs` на подделке
  Web Speech API. Прежде чем менять `src/lib/tts.ts`, запусти `npm run test:tts`
  и убедись, что твоя правка не ломает ни один сценарий: они друг другу
  противоречат, и «очевидное» исправление одного обычно возвращает другой.
- **Родительный падеж множественного числа непредсказуем** у мужского и женского
  рода с ударением не на окончании: `πατέρας → πατέρων`, но `άντρας → αντρών`.
  Правила нет, есть история каждого слова.
- **Женский род на безударное `-η`** даёт и `-ες`, и `-εις` (`νίκη → νίκες`,
  `πόλη → πόλεις`). По окончанию не различить.
- **Глаголы на `-ώ`** бывают двух спряжений (`αγαπώ` как `-άω`, `μπορώ` как
  `-ούμε`). Формы надо задавать явно.

## Проверка интерфейса браузером

Установлен плагин `playwright` — есть навигация, клики, ввод, снимок DOM,
измерение геометрии. Этим уже найдено то, что чтением кода не находилось:
разбор без перевода, 471px фильтров вместо слов, гонка с `revokeObjectURL`.

Полезные приёмы:

- **Состояние сеют через IndexedDB** (`keyval-store` → `greek-vocab:progress`),
  а не прощёлкивают двадцать карточек. Так можно вывести любой тип упражнения:
  положи карточку нужного `kind` с просроченным `due`.
- **Вёрстку проверяй измерением, а не скриншотом.** Скриншоты Playwright пишет
  в свой изолированный каталог, Read их не видит. `getBoundingClientRect` плюс
  сравнение с `clientWidth` надёжнее и точнее.
- **React не замечает прямой записи в `input.value`** — он отслеживает значение
  сам. Для ввода нужен `browser_type`, иначе фильтр не применится и решишь,
  что поиск сломан.
- **Синтетический `.click()` не даёт `pointerdown`**, поэтому разблокировка
  озвучки не сработает. Для проверки звука нужен настоящий `browser_click`.
- В headless Chromium **греческий голос есть** (Melina), и `onstart` приходит.
  Поэтому дубли озвучки, которые ловятся только в Safari, здесь не воспроизводятся.

## Грабли

- **YAML:** двоеточие внутри незакавыченной строки ломает разбор.
  `note: тип на -εις: οι πόλεις` → нужны кавычки вокруг всего значения.
- **`npm run check` обязан работать в чистой копии.** Ничто в нём не должно
  читать `src/generated/deck.json`: этот файл в git не хранится, а режим
  `--check` его намеренно не создаёт. Локально он лежит с прошлых сборок,
  поэтому такая зависимость проходит незамеченной и падает только в CI.
  Проверять так: `rm src/generated/deck.json && npm run check`.
- **HTTP-заголовки только ASCII.** Кириллица в `User-Agent` роняет `fetch`.
- **Прогресс живёт только в браузере.** Смена порядка ступеней или набора типов
  карточек меняет расписание у того, кто уже занимается. Предупреждай об этом.
- **`<StrictMode>` вызывает эффекты дважды.** Это не баг React, а способ найти
  неидемпотентные побочные эффекты — и он уже нашёл двойное проигрывание
  озвучки. Отключать StrictMode нельзя; чинить надо сам эффект. Любая функция,
  которую вызывает `useEffect`, должна выдерживать повторный вызов: отменять
  не только текущее действие, но и своё же отложенное через `setTimeout`.
- **Одинаковый перевод у двух разных слов — баг, а не мелочь.** На карточке
  RU→EL видно «дешёвый», а какое из двух слов вводить — непонятно. То же в
  подсказке к пропуску: она переводит предложение, и если перевод пропущенного
  слова годится обоим — угадать нельзя. Переводы надо разводить уточнением
  в скобках, а разницу объяснять в `note`: он виден в разборе после ответа.
  Сборка предупреждает сама, когда перевод одного слова целиком входит
  в перевод другого (`ambiguousTranslations` в `scripts/build-deck.mjs`).
- **Скачивание файла: якорь в документ, `revokeObjectURL` — с задержкой.**
  Safari игнорирует `click()` на неприсоединённом якоре, а немедленный отзыв
  blob-ссылки обрывает чтение, и файл сохраняется пустым. Из-за этой пары
  перенос прогресса не работал вовсе.
- **«В приложении старое слово» — сначала посмотри дату сборки.** Приложение
  стоит на домашнем экране и работает офлайн, поэтому исправленный словарь
  и устаревшая копия выглядят одинаково: слова на месте, ошибок нет, просто
  примеры не те. Дата — в приложении: Настройки → Версия, там же кнопка
  «Проверить обновление». Пока не сверил дату, не чини словарь: правка уже
  может быть в нём.
- **Служебного работника нельзя регистрировать по событию `load`.** Именно так
  и было, и обновления не доезжали месяцами: иконку на домашнем экране iOS не
  перезапускает, а размораживает, `load` второй раз не наступает, спросить
  сервер о новой версии некому. Регистрация живёт в `src/lib/pwa.ts` и
  переспрашивает при каждом возвращении в приложение. Обратно на `load`
  не переноси, даже если так короче.

## Готовые навыки

Не изобретай процесс заново — он уже описан:

- `/add-words` — добавить слова из скриншотов, списка или текста: разложить
  по темам, проставить артикли, проверить дубликаты, отчитаться цифрами.
- `/publish` — выложить или обновить сайт на GitHub Pages.

## Автопроверка

После правки любого файла в `data/` хук прогоняет `npm run check` и, если
проверка упала, возвращает вывод целиком. Настроен в `.claude/settings.json`,
сама логика — в `scripts/hooks/check-data.sh`, читаемым шеллом.

Это не отменяет ручной проверки: хук ловит поломки, но не подскажет, что
перевод неточен или тема выбрана неудачно.

## Чего не делать без спроса

- Не коммитить и не пушить, пока не попросили.
- Не менять лимиты нагрузки (`newWordsPerDay` и прочее) — это настройки
  пользователя, они живут в приложении.
- Не удалять слова из `data/`. Если слово лишнее — спроси.
- Не трогать `tmp/` — там скриншоты владельца, они вне git.
